# Security contract

Read [scope](../PROJECT_SCOPE_INF2006.md) and [API](API.md). This defines controls; evidence/threat-control-map.md records their actual implementation and proof.

- Use framework password hashing and database sessions; no custom cryptography or frontend token store.
- Share signing configuration. Use Secure/HttpOnly cookies and SameSite=Lax under HTTPS. Verify logout/expiry across instances and plan expired-session cleanup.
- Enforce ownership on every cart/order lookup and operator permission on every analytics request. Imported identities are not active logins by default.
- Customer-segment display references reduce unnecessary account-data exposure; they are not authorisation or anonymisation. Never expose login usernames, names or email through segment rows. See the [serving contract](ANALYTICS.md#segment-serving-contract).
- Enforce CSRF on browser mutations including HTMX. Validate bounds, use parameterised ORM queries and escape untrusted values.
- Derive owner/prices/totals on server. Transactions, stock constraints and idempotency protect concurrent/retried checkout. Simulated payments only.
- Disable production debug; restrict allowed hosts; configure trusted proxy handling and safe redirects correctly.
- Private RDS/S3, restricted security groups/IAM and non-superuser runtime DB role. Production uses separate migration-owner and runtime logins; the bootstrap rejects unsafe existing roles/ownership. See [database runtime preparation](AWS_INFRASTRUCTURE.md#database-runtime-preparation). Local Compose retains its developer-owned database; document lab limits honestly.
- AWS uses Secrets Manager for database credentials and the shared Django signing key, retrieved through runtime role credentials (the Learner Lab denies creating IAM roles, so every runtime identity is the broad `LabRole`; least-privilege IAM is a stated gap, threat T19). Unavailable storage or retrieval blocks deployment; never fall back to plaintext user data or launch-template values. Startup retrieval and caller schemas are defined by the [runtime handoff](AWS_INFRASTRUCTURE.md#secrets-manager-startup-and-alb-boundary); production refuses plaintext fallback and static SDK credentials. Local development keeps its documented environment configuration. Examples contain placeholders. Never commit tokens, private keys, passwords, Terraform state or real personal data.
- Log request IDs, durations and sanitised errors, not credentials/cookies/raw personal payloads. Follow brief redaction rules for cloud evidence. Implemented by `config.middleware.RequestLoggingMiddleware` and `config.jsonlog`: one JSON line per request on standard output with request ID (an incoming `X-Request-ID` is reused only if short and plain; also returned as a response header), method, path without the query string, status, duration in milliseconds, numeric user ID (never resolved just for logging) and the exception class on failure. Exceptions are logged as class plus a few stack frames only, never the message, source lines, locals, headers, cookies or bodies. Messages from Django's `django.security.*` loggers are replaced by a fixed one because they can echo request headers (the CSRF check logs the rejected Referer with its query string); the logger name and request ID still identify the rejection. Health probes and static files log at DEBUG unless they fail. Gunicorn's access log stays disabled.
- Optional caching must not bypass authorisation or share personalised content. Restrict cache access and tolerate its loss for disposable reads.

Negative tests: unauthenticated checkout, foreign cart/order access, non-operator analytics, missing/invalid CSRF, quantity/price manipulation, duplicate checkout and anonymous S3 access. Record expected/actual results; a generic security claim is insufficient.
