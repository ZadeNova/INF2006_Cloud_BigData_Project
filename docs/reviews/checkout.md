## Coordinator notes

- Code re-read on 20 September 2026: `checkout()` locks cart rows by the pinned IDs only and reads `quantity` from the locked row at submit time; the pin is stored per session and overwritten by every checkout page render; both winner-return paths (`IntegrityError` handler and the `len(locked_items) != len(item_ids)` branch) return the existing order without comparing fingerprints. CHK-001 and CHK-002 are confirmed as described.
- **Fix implemented (not yet committed when this note was written):** the form posts a fingerprint of the displayed lines; the server compares it with the locked current cart (CHK-001) and with an existing order's stored fingerprint for the same key (CHK-002). The session-held item IDs are gone, API.md, SCHEMA.md and the batch 4 plan are updated, and the pin-based tests were reworked. **Behaviour change for the owner to note:** an item added, removed or re-quantified after the review page loaded now blocks the order until the user reviews again (previously an added item stayed in the cart and the reviewed items were bought).
